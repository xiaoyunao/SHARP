# SHARP 服务器 v2：首版运行与网站交接

2026-11-18，所有排程日期和时刻按北京时间。用户本轮已授权服务器归档、停用v1自动任务并部署v2；这覆盖此前仅本地研发的限制，main分支保持。

## 入口与职责

v2使用4397场冻结共用表，执行名前缀为MP、TJNL4、TJNL5、FOLLOW，同四位后缀对应相同ICRS中心；YSO_ORI/CYG继续独立。服务器保留原生产三个目录和公开产物路径，新排程/操作代码在 `/pipeline/xiaoyunao/targeted_observing/`，配置与状态在 `/pipeline/xiaoyunao/v2/`。

- 每天12:00启动 `server_service daily`：更新已完成实拍历史，生成当夜计划，然后提交前一观测夜的known/unknown Slurm处理作业。
- 每分钟 `server_service tick`：处理网站请求事件、恢复错过的中午计划、在迟到数据稳定后补交处理作业。重启后也做一次tick。它不在没有新事件时反复重算计划。
- **没有自动生成后随候选或跨夜关联**。网站决定candidate和观测参数，服务器只调度明确收到的JSON。每次新/更新命令都有持久事件，重排读取该夜全部有效JSON。
- known/unknown共用经过结构、WCS、真实曝光时间及夜次校验的科学L2清单，不按MP或四位编号通配符决定资格。有效零匹配夜与全部输入错误夜分开表达。
- MPC继续暂停。known未来可在联系人确认并单独启用后由服务器报；unknown上报只在网站，旧服务器unknown watcher/submit/跨夜自动入口已退役。配置不允许打开unknown自动报。

## 网站提交一个candidate

JSON最小格式：

```json
{
  "candidate_id": "example_candidate",
  "night": "20261118",
  "field_id": "2630",
  "start_time": "2026-11-18T23:30:00+08:00",
  "frames": 5,
  "exposure_s": 30,
  "filter": "r"
}
```

`night`是当晚黄昏的YYYYMMDD；次日凌晨仍属于这一观测夜。field_id必须是带前导零的四字符文本，开始时间必须带时区，帧数/秒数为正整数，波段为小写g/r/i/z。candidate_id只允许字母数字开头以及字母、数字、点、下划线、短横线，最长80字符。服务器生成执行名 `FOLLOW_2630`；candidate身份在JSON/逐帧表中另存，不混进场号。

建议网站经现有SSH上传到临时文件，然后**在服务器执行**：

```bash
cd /pipeline/xiaoyunao
/pipeline/xiaoyunao/v2/submit_followup.sh /absolute/path/candidate.json
```

也可以直接调用：

```bash
/home/smtpipeline/Softwares/miniconda3/bin/python -m targeted_observing.server_followup /absolute/path/candidate.json
```

成功返回JSON含accepted、实际night/start_time、deferred、acceptance_cutoff、请求路径、事件路径和状态路径；失败返回accepted=false与error，退出码2。无需新增HTTP端口或把SSH凭据写进配置。接口只入队，不替望远镜发控制命令。

投递后文件位于：

| 项 | 路径 |
|---|---|
| 当夜有效请求 | `v2/runtime/followups/<night>/<candidate_id>.json` |
| 每次提交/更新事件 | `v2/runtime/events/<night>/*.json` |
| 事件已处理记录 | 对应`*.result.json` |
| 排程结果/原因 | `v2/runtime/followup_status/<night>/<candidate_id>.json` |
| JSON格式/身份错误 | `v2/runtime/followup_queue_errors/<night>.json` |
| 暂时失败、等待重试 | `v2/runtime/event_errors/` |
| 旧版同源JSON | `v2/runtime/followup_revisions/<night>/<candidate_id>/` |

网站若直接SFTP投递，应先写非`.json`临时文件，再原子改名为`<candidate_id>.json`；tick能发现这种投递，以服务器文件ctime判断到达时间。推荐使用提交命令，立即获得格式、时效及实际入队夜次。队列按夜隔离，已受理旧夜的请求不会自动继承到第二晚，旧文件保留审计。

**后随受理截止为北京时间17:00；若当晚已发布计划更早启动，则以计划启动时刻为截止。** 截止后新提交的当夜请求转入下一可受理观测夜，期望开始时间整体平移相应天数、保留当地时分；返回实际night/start_time和deferred=true，请网站据此显示，勿仍标为当夜受理。比如11/18 17:01提交11/18 23:30，实际入队11/19 23:30。午夜后提交昨夜请求则转到今天黄昏；不再改昨夜列表。直接投递的跨夜迁移另存`deferred_followups/<原night>/`审计。

12点前的命令在中午合并处理；12点至截止前的每次命令各有一次重排事件（轮询间隔≤1分钟，另加排程计算时间），每次均读取全队列。最高优先级为后随，再安排YSO预约及TJN/晨昏；偏好准确首曝时刻，冲突时尽量顺延到当夜仍合法的时段，不受5分钟偏好阈值硬截断。每个结果给出实际名义首曝、与请求的偏差、帧数；约束冲突或整段不可见则明确未安排及原因。

17点前最后提交但尚未处理的事件，可以在实际启动前完成收尾；到计划启动时刻禁止重新发布，当夜未纳入列表的请求转下一夜。历史更新在截止后只记账，供次日中午使用。计划计算或画图若跨过启动时刻，也会阻止发布；画图结束、移动公开文件前还须保留至少30秒预算。生产服务不调用开拍后前缀重排/remaining机制。静态控制器须在开拍前装载最终版本；有空档的列表仍须遵守START_TIMES的分段时刻。

## 当前overhead预算

- 每帧读出18秒，包含最后一帧读出；同场连续120秒曝光按138秒/帧计，30秒曝光按48秒/帧计。
- 初次设片或改变波段加24秒；保持同波段不再加。滤镜与slew按顺序相加，没有假定重叠执行。
- 同一指向转场0秒；不同指向采用`9.11 + max(11.95*sqrt(abs(ΔRA)), 12.30*sqrt(abs(ΔDec)))`秒。角差单位度，RA取跨0°最短差，不乘cos Dec；两轴取max。例如纯RA移动1°约21.06秒、3°约29.81秒。
- 整晚首次未知起始指向预留90秒转场，再加24秒设片。以上是现用规划预算；实际观测执行误差不会被静态TXT自动纠正。

每次发布先写不可变版本 `v2/runtime/plans/<night>/<revision>/`，再原子替换各文件；发布完成标志为 `v2/runtime/published/<night>.json`。旧的多余cycle图移入版本目录，避免网站glob读到v1残图。底图历史计数读取真实去重曝光账本，只把实拍WCS中心与共用场/YSO中心相差≤0.1°（容纳实测指向偏差）的曝光计入；不按旧后缀迁移或把其他旧指向强分到最近新场。匹配/未匹配数量随图写`history_mapping.json`。TXT仍是原八列、滤镜小写，连续相同曝光压缩为重复数，逐帧JSON/CSV保留展开记录和candidate/请求版本。

**控制器TXT没有WAIT，也不会自己重载。** 正常可连续填满时发布单段；若后随、天空约束或无安全目标造成必须等待，`<night>_START_TIMES.json` / 发布标志中的`requires_timed_segments=true`，应按`segmentNN.txt`各自固定启动时间执行。此时总TXT是汇总，不能一口气顺序执行并指望它等待；网站接入时必须展示该标志和分段文件。任意设备延误也不会被静态TXT自动纠正。

## TJN实拍历史与采样

- `v2/runtime/history.sqlite`：曝光UID去重的真实曝光和known目标检出，按夜增量更新；重处理覆盖旧测量，绝不从计划增加计数。编号缺失时保留可识别的临时名字，坏/masked质量值不会中断整夜导入。
- `history_exposures.csv`：可直接检查的全部科学曝光列表；`history_tjn_measurements.csv`：目标、曝光文件、时间、滤镜、误差和质量标志。
- `tjn_sampling_status.json`：每目标有效点数、合格夜数、每夜跨度、曝光间隔、跨夜基线、已有周期假设的相位覆盖和是否达到采样门槛。g/i/z不充作r点。
- 默认参考原年度设计：误差≤0.05mag的有效r点，100点、10夜，每夜至少5点且连续采样段跨度≥30分钟，段内最大间隔≤30分钟，基线≥21天；有既有周期时基线至少3个最长候选周期，并考察所有候选周期20箱中的≥80%相位覆盖。中位误差门槛0.03mag。
- 队列按缺失点/夜、连续性、基线等待、相位新颖性、亮度和冻结科学角色加权，重叠场按对象去重。满采样的对象释放致密时间；未满的优先补。默认驻场最多5张，但随场数和实测slew缩短，避免轮巡间隔过长。最终按真正安排的中点再验留场≥80%。
- 采样就绪不等于精确光变、标定合格或唯一自转周期；后两者在状态中明确未认定。已有文献周期是排程先验，不是本项目新测量。原参考帧质量还不能代替真实科学遮罩和光晕核查。
- known完成后立即更新真实历史，并产生历史更新重排事件；不用等慢的unknown搜寻结束后才让今晚TJN利用昨晚的新检出。截止前该重排仍合并全部网站后随；截止后只保存历史供次日使用。

## 单夜处理、恢复与检查

科学清单在 `v2/runtime/manifests/<night>_science.json`，L4也写副本及兼容`<night>_file_manifest.txt`。标定/调焦、坏源表、无WCS、缺真实时间、错夜和重复曝光均记录拒绝原因；known/unknown读取同一份清单，输入mtime/大小中途变化即失败，避免known剔错夜、unknown却继续处理旧图。

实际时标统一为EXPSTA/EXPEND中点，回退开始+EXPOSURE/EXPTIME的一半，不默认30秒；known的epoch/MJD、unknown关联与复核导出时间一致，原L2不改。物理滤镜随测量进入导出。新速度范围3–750″/h，保留静态源、密集组、known掩膜和形态门槛。密集组/复核超限会在状态中列出，不能当作已逐候选验收。

`v2/runtime/processing/<night>.json`区分无有效输入、运行、失败和该清单快照完成。完成不代表数据传输永远结束；新输入会触发新版本处理，旧结果/派生工作先放到`result_revisions/<night>/`，原图和L1/L2不动。已知提取完成不依赖MPC回执。Slurm作业、输入稳定等待与重试在`processing_queue/`；最多自动尝试3次后需要诊断。

