### 2.2 新确认：选时段的分数与去重后的实际收益不一致

位置：`targeted_observing/annual_simulation.py::pick`，固定提交约57–102行。

当前逻辑是：

1. 每个候选场累加所含对象的价值。
2. 对每个起始时段，将最高的若干**场分数直接相加**，按这个数值排序时段。
3. 进入一个时段后，才用 `used` 去重并贪心挑场。
4. 只要当前时段能选到场，就立即返回，不再比较其他时段的去重收益。

因此，多个候选场覆盖同一个高价值对象时，可能虚高某时段的排序分数。已有的对象去重并不能自动解决这个问题：它发生在时段排序之后。

#### 本轮实际执行的最小反例

允许选择最多两个场，两个时段均视为满足输入的几何条件：

| 时段 | 可用场 | 各场包含的独立对象 | 排序前场分数之和 | 可获得的去重价值 |
|---|---|---|---:|---:|
| 0 | A1、A2 | 两场都只有A，A价值10 | 20 | 10 |
| 1 | B1、C1 | B、C各价值6 | 12 | 12 |

当前函数返回时段0，且只选A1；去重价值为10。穷举这个四场小测试得到的更好结果是时段1的B1+C1，价值12。

在 `completion=None` 和启用完成机会预测两种输入下均重现。另检查了没有可用场时仍正确返回None。

**结论的尺度：**这是已复现的局部排序问题，不是“全年产额损失20%”的证据，更不是修复后一定达到101颗的证据。全年影响必须在真实菜单、相同天气序列下重新量化。

复现原版本：

```bash
python tests/reproduce_pick_start_issue.py
```

检查真实仓库函数（不导入整个SHARP、不访问网络）：

```bash
python tests/reproduce_pick_start_issue.py \
  --source /path/to/SHARP/targeted_observing/annual_simulation.py \
  --require-fixed
```

原版本加 `--require-fixed` 应返回非零；修复版本应在这个反例上通过。该测试只抽取顶层 `pick`；若重构使其依赖新的辅助函数，应把测试迁入仓库原生测试环境，不要为了适配独立脚本牺牲设计。

#### 建议修复

每个候选时段先形成去重后的场组合，再比较该组合的独立对象收益；近似并列时的时角轮换也应基于可比较的去重收益。保留当前基线以便做配对对照。

随后用已有 `numeric_visits()` 计算真实访问路线，在相同两小时总预算内比较有效点数、有效夜门槛、完成机会与科学任务收益。可以先实现少量候选组合重评分/邻场替换，而非昂贵的全年全局最优。

注意：原始未去重的top分数可以作为搜索上界，不应直接当最终收益。用上界裁剪时需证明不会丢掉更好组合；测试只有四场，不能把穷举方案直接套到全年。

### 2.3 已有的几个问题仍未改变

- 实际转场耗时已计入 `numeric_visits()` 与执行账本，不能说“忘了算转场”。缺的是它参与选场/选时段的比较。
- `science_priority_strength=0` 同时使 `completion_forecast` 失效。纯文献权重消融与完成机会预测必须拆成独立开关，否则比较混入两个变化。
- `pick()` 内有21日、10夜、100点等硬编码。当前与基准配置一致，但应从同一quality配置读取并做非默认阈值回归，防止未来改门槛后预测与验收不同步。
- 当前通用 `quality_lightcurve` 完成后对象价值归零。特殊慢转/模型验证任务需要独立的任务状态，不能只在标签表里写科学价值而排程仍在通用达标后停止。

## 三、当前产额的可用结论

固定提交的四场×每次两帧、每夜上限两小时：基准合格光变P10/P50/P90为36/42/47；乐观测光为55/62.5/70。24组标准两小时情景均未在200次模拟中达到101颗，这不是总体成功概率严格为零的证明。

恢复包有192个年度曾采样对象ID，是200次实现至少被采样一次的并集；不是单个模拟年192条曲线。本轮重新求和 `quality_probability` 得到期望合格数量41.690，与中位数42应区分。`control` 与 `known_other` 的期望合格数合计34.170，约占81.96%。这说明申请书必须区分已有周期对象重测、周期争议复核、首次周期、形状/极轴新几何约束，而非把所有合格曲线叫新周期。

四小时、八场、r18单张误差0.010mag的实验达到中位117，但同时改了时间与测光性能，且性能未经现场证实；不能把它当已获批两小时模式的预测。

这次发现的局部优化问题说明仍有必要优化，但不能据此预支百颗结果。保留用户全年 >100颗准确光变的目标，报告真实缺口，不降低门槛或改成三夜计划来规避。
