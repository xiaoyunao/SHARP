### 必须保持的来源说明

1. 192 个 ID 是 200 次模拟中至少被采样一次的并集，不是单个模拟年观测的对象数，更不是 192 条合格光变。
2. 全局位置图使用此前 15,366 个轨道的两体传播，适合度量级的规划示意，不用于分角秒定位或执行清单。
3. 局部场和特殊目标高度图使用本次新取得的兴隆站心 Horizons 星历；代表月图仍不能证明每个月所有日期都可见或不可见。
4. 图中星等是 Horizons/模型预测 V，不能直接等同本机 r120 的测光精度，更不能从白光极限 W≈20.8 推出高精度 r 光变能力。
5. 月度代表夜中的“2 h 可用”仅指审查级中心高度、太阳和月角距条件，未扣预约、晨昏保留、天气、亮星、转场；原调度还有更严格的时间采样守卫。

## 3. 现在的 Trojan 是否只按亮度和天区选？

并不是。当前 `science.py` 已读入 LCDB、Li2025、2026 形状/自转模型、DAMIT、TESS DR1 与 TESS2025。真正生成报告的年度队列在 `annual_simulation.py` 中使用文献权重，而不只是早期 `annual_trojan.priority`。

实际科学乘子为：`1 - strength + strength * literature_weight`，默认 `strength=0.25`。

| 角色 | 实际乘子 |
| --- | ---: |
| alias_review / unknown_or_weak | 1.000 |
| slow_candidate | 0.925 |
| control | 0.800 |
| known_other / literature_unchecked | 0.775 |

它再与预期测光误差、同场独立对象数、已完成进度和剩余完成机会相结合。因此科学权重已经存在，但只是温和修正。当前人工审查表只专门登记了 2223 和 22180，没有给双叶形状、慢转、多频、双星和任务配套建立独立科学任务。

对 `object_summary.csv` 的质量概率求和，可以得到各类别的期望合格数量；此处不能把各类别中位数相加。

| 类别 | 曾采样独立 ID 数 | 期望合格数量 |
| --- | ---: | ---: |
| control | 71 | 27.345 |
| known_other | 52 | 6.825 |
| unknown_or_weak | 29 | 5.715 |
| alias_review | 1 | 0.805 |
| literature_unchecked | 39 | 1.000 |
| 总计 | 192 | 41.690 |

已知周期/模型两类占期望合格产额约 82%。这不否定重复观测的科学价值：新视向振幅、光变形态、极轴/形状模型检验以及长期变化都可能值得做。但项目申请必须写出其具体问题，不能把所有合格曲线都写成新周期。

### 任务目标与快转目标的边界

NASA当前任务表列出 Lucy 的 Eurybates 飞掠为2027-08-11、Polymele为2027-09-14、Leucus为2028-04-18、Orus为2028-11-11、Patroclus–Menoetius为2033-03-03。Hektor不在该任务目标表中。

本次12个代表夜中，Hektor暗夜最高约22.52°，Leucus约28.41°；Eurybates、Orus、Polymele只有很低的过中天窗口，未通过这里采用的32.8°固定场中心门槛。Polymele还约V19且低振幅。应将这些列为“需要逐夜确认的条件目标”，不要为了任务故事直接计入稳定年度产额。代表夜结果不是全年极值证明；偏置场中心和更短窗口也需要另算。

Kiss2025的快转对象13383、38615、228155很有科学价值，但本年度代表夜分别受低高度或V≈20–20.4限制。第三个编号应为**228155**；论文正文局部288155是笔误，表格为228155。它们适合列为条件合作/专项试测对象，而不是由W20.8极限推定可获精确r曲线。

## 6. 优先修改的实现要求

### P0：科学任务与完成条件

保留统一的高质量光变指标，并新增可并存的科学标签。一个对象可以同时是control、Lucy目标和binary；不能被单一分类覆盖后就失去其他科学优先级。

推荐登记字段：

`object_id, science_tags, source_doi_url, source_table_row, candidate_periods_h, period_quality, amplitude_mag_band_epoch, science_question, observing_mode, required_baseline_days, phase_coverage_goal, max_gap_days, event_ephemeris_required, priority, review_date`

至少分开：

- `photometric_complete`：达到统一的测光、有效点、有效夜和基线要求。
- `period_solution_complete`：候选周期区分、相位覆盖、精度及别名检查达到目标。
- `science_case_complete`：该对象的形状、慢转、多频或事件任务已达到其专属条件。

年度数目按对象ID去重，同一对象可以出现在多个科学子项，但总计不能重复加和。保留“合格曲线”“可信周期”“新周期”“冲突复核”“特殊目标任务”分别计数。

### P0：导出实际全年坐标与观测时间

采用随包的 `export_plot_data.py`，从已有的 `selected_nominal` 导出小型资料，不重新计算排程：

```bash

  --output /path/to/SHARP/targeted_observing/docs/annual_reports/plot_data \
  --start-date 2026-11-01 --stop-date-exclusive 2027-11-01 \
  --source-commit a5cb9454e56771ebe4211b7a544412056cce4c40
```

导出 `fields.csv`、`exposures.csv.gz`、`night_index.json`、`manifest.json`。默认要求365个连续夜次，明确的零计划夜也应保留；缺坐标必须报错，不能填0或复制其他天。

随后直接批量画实际全年图和每夜高度/甘特图：

```bash

  --output /path/to/annual_plan_figures \

```

绘图器读取真实夜次索引，包含零计划夜；不重新分配观测，也不重跑天气。单夜fixture已验证此入口，完整365夜输出仍需原始年度产品。

### P1：真实转场成本参与选场

当前代码已将实际转场消耗计入执行/产额，问题是选出组合时尚未用真实路线重新比较。不要把这一点写成“漏算转场”。

最小改进：保留当前贪心基线，对分数最高的少量候选组合，调用已有 `numeric_visits`，比较实际可获得的有效点、完成概率和科学目标增益；再做邻近场替换与访问排序。无需先实现昂贵的全局最优算法。加入自由场中心候选，用计划访问时刻检查留场，不强求整夜所有时刻都在场内。

四场、驻场两张的年度结果，间隔中位数约135s，但P90约1231s，即20.5min。相邻两帧的短间隔不能代表真正的轮巡回访。图必须显示间隔分布和时间条带，明确短驻场间隔与长轮回间隔。

### P1：慢转对象使用低频长期模式

慢转对象的研究常更需要跨夜、跨周的相对零点稳定，而不是同一晚持续大量点。优先利用同场/邻场采样，或在现有两小时预算中比较少量特殊源访问块。可比较特殊任务占年度Trojan时间的10%和20%两种情景，并将对应总产额损益报告出来；这个比例是待比较的策略，不是额外获批时间。

跨夜不能逐夜减去均值来“校正”慢光变。需要固定r体系、颜色项与消光处理、参考星网格、场版本切换时的零点连接，以及距离/相角和观测几何的一致处理。

### P1：跨季节基线与周期恢复

当前年度质量门槛使用首末夜之差，允许长断档。例如617中位13个好夜对应259天基线。这不是连续259天监测。现有周期注入确实使用真实时间戳，已保留窗函数影响；需要补充的是最长断档、单campaign完成、跨季节合并完成，以及跨季节振幅/形态变化的模型。

对跨季节恢复率，加入分段零点/幅度或适用的几何模型，并保留稳定形状的理想参考情景。不要把“全年基线很长”自动当作慢周期约束充分。

### P1：晨昏几何与收益图

原代码五访基线可继续用于试观测。下一步应比较晨间十访的后对齐排程，观察能否利用窗口后段较低距日角的场；当前十访在整小时起点预筛，因此未覆盖45–55°包含实现选择的影响，不能当成十访的物理必然。

用实际成功短弧定义跨夜恢复图。当前至少两/三夜面积是有有效帧覆盖，不等价于每夜均形成合格tracklet。年度面积对比中：五/十访名义独立足迹6180.93/3812.19deg²，合格短弧核心5772.11/3513.03deg²；天气实现0的3745.08/2432.07deg²不是200实现的中位数，也未施加星等检出概率。日对交集面积累加应标注deg²·夜对，不能称为独立面积。月度中心距角分箱后的整足迹可跨箱重叠，不能作总和为100%的面积堆叠。

### P2：显示和策略对照的小修正

- `sigma_r18`至少保留三位小数；0.025、0.015、0.010不能显示成0.03、0.01、0.01后让96.5与117看起来来自相同情景。
- 当前 `strength=0` 还会关闭完成机会预测。做纯科学权重比较时，应将科学权重与完成预测开关分开，使用相同天气随机序列。
- 夏季无合适Trojan场时输出明确空闲区间和原因，不为铺满日历强填低收益场。当前完整两小时菜单的8月为零，7月很少，这是应当展示的年度结果。
